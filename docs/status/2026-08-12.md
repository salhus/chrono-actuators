This is the run that demonstrates finite output impedance. Two regimes are
visible in one table:

**Unsaturated** (`t <= 0.451`) — the back-EMF feedforward has bus headroom, so
commanded current `i = 5 / (Kt * N * eta) = 1.3889 A` and commanded effort
`tau = Kt * i * N * eta = 5.0 N` are delivered exactly.

**Saturated** (`t >= 0.501`) — terminal voltage clamps at `V_bus`, current falls
as `i = (V_bus - Ke * omega_motor) / R`, and effort droops with it.

Checked against theory:

- predicted saturation onset at `v = (V_bus - R * i_des) / (Ke * N)
  = (6 - 1.389) / 4 = 1.153 m/s` — droop begins in the row immediately after
  `1.1250 m/s`
- at `v = 1.2378`: predicted `i = (6 - 0.2 * 24.756) / 1 = 1.049 A`, observed
  `1.0564 A` (difference is implicit-integrator lag on a 1 ms winding constant)
- effort at that point: `0.2 * 1.0564 * 20 * 0.9 = 3.803 N` — matches
- velocity asymptotes toward `omega_nl_out = V_bus / (Ke * N) = 1.5 m/s`
- stall effort `Kt * (V_bus / R) * N * eta = 21.6 N` — matches printed value

Before the bus limit was added, this demo produced a perfectly linear velocity
ramp with current pinned at 1.3889 A indefinitely — the signature of an ideal
effort source. The model now runs out of speed the way a real machine does.

### Defects found and fixed

Three real defects surfaced today, all by running the demos and checking the
numbers against theory. All three were invisible to the test suite, which was
green throughout:

1. **Stiff ODE path had never executed.** `ChSystemNSC`'s default PSOR solver
   aborts when `ChExternalDynamicsODE` injects KRM blocks. The
   `ChActuatorDynamics` force-injection path and its sign convention were
   therefore unverified until the direct solver was configured. Sign convention
   was found correct — positive commanded effort moves the body in the positive
   direction, no inversion needed.

2. **`demo_ACT_shaft` produced silent zeros.** `ActuatorCommand::enabled`
   defaults to `false`, which gates effort to zero without erroring. The default
   is correct and deliberate for the hardware path, so it was kept; every demo
   now sets it explicitly and the default is documented.

3. **`ElectricActuatorModel` was an ideal effort source.** The back-EMF
   feedforward in `CommandToVoltage` exactly cancelled the `-Ke*omega` term in
   the ODE RHS with no ceiling on terminal voltage, so commanded current was
   achieved at any speed and no-load speed was infinite. Fixed by saturating at
   `V_bus`.
